# درخواستِ کوچک به «کلادکد CRM» — بازهٔ تاریخیِ دلخواه برای /finance

اندپوینتِ `GET /a2crm/v1/tg/finance` عالی کار می‌کند (بیت‌به‌بیت با صفحه). فقط یک قابلیت کم است:
**بازهٔ تاریخیِ دلخواه.** الان فقط `month` (ماهِ جلالی) را قبول می‌کند و `from`/`to` را نادیده می‌گیرد
(تست شد: با `from/to` همان ماهِ جاری برمی‌گردد).

## خواسته
پارامترهای اختیاریِ `from` و `to` را اضافه کن (هر دو **جلالیِ `YYYY-MM-DD`**). اگر **هر دو** داده شدند،
به‌جای تبدیلِ `month`→بازه، همان بازه را مستقیم استفاده کن (با همان هلپرِ موجودِ `a2_jalali_to_gregorian`
برای تبدیل به میلادی، و همان تابعِ مشترکِ `a2_crm_commission_compute`). صفحهٔ پورسانت خودش هم بازهٔ آزادِ from/to
دارد، پس زیرساختِ محاسبه از قبل هست — فقط باید این دو پارامتر روی route خوانده و به همان تابع پاس شوند.

- اولویت: اگر `from`+`to` بودند → بازهٔ دلخواه. وگرنه اگر `month` بود → همان رفتارِ فعلی. وگرنه → ماهِ جاری.
- در پاسخ، `range` را همان بازهٔ میلادیِ واقعی برگردان (مثل الان). `month`/`month_label` را می‌توانی برای بازهٔ دلخواه خالی بگذاری یا حذف کنی.
- `fixed_salary`/`carry`/`deposit`/`bucket` مثل قبل کار کنند.
- خطا: اگر فقط یکی از from/to داده شد یا تاریخ نامعتبر بود → همان `{"ok":false,"msg":"..."}`.

## بعد از ساخت
ربات سمتِ خودش آماده است: `crm.finance(date_from=..., date_to=...)` این‌ها را می‌فرستد. کافی است اندپوینت
`from`/`to` را بخواند. وقتی زنده شد خبر بده تا دکمهٔ «بازهٔ دلخواه» را در ربات فعال و تست کنم.
