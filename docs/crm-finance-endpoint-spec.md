# CRM Finance Endpoint — spec (نسخهٔ ۲، مطابقِ ساختارِ واقعیِ صفحهٔ پورسانت)

بر اساسِ گزارشِ کاملِ کلادکد CRM از `commission-report.php` (a2-crm-plugin v3.16.1). هدف: رباتِ مدیریتِ داخلی
یک نمای فقط‌ادمینِ **«حساب مالی»** دارد که برای هر ماهِ جلالی، **همان اعدادِ صفحهٔ پورسانت** را نشان دهد.

> ⚠️ کلیدِ درستی: این اندپوینت باید **همان محاسبهٔ موجودِ `commission-report.php` را دوباره‌استفاده کند**
> (توابعِ `a2_crm_commission_split_amounts` و حلقهٔ per-order و نرخ‌های هاردکد)، نه پیاده‌سازیِ دوباره —
> تا عددِ ربات مو‌به‌مو با عددِ صفحه یکی شود.

> Phase 1 = **READ ONLY**. Phase 2 (بعد از تست) = نوشتنِ دریافتی/مخارج + ذخیرهٔ حقوق‌ثابت/مانده per-ماه.

---

## واقعیت‌هایی که طراحی را تعیین می‌کنند
- **بُعدِ پرسنل وجود ندارد** → خروجی «حسابِ یک نفر»، نه per-agent.
- **هیچ تجمیعِ ماهانه‌ای ذخیره نمی‌شود** → اندپوینت لحظه‌ای از سفارش‌ها + ۳ آپشن حساب می‌کند.
- **واحد = ریال** (`woocommerce_currency=IRR`). خام برگردان؛ تبدیل به تومان کارِ نمایشِ ربات است.
- **`fixed_salary` و `carry` منبعِ دیتابیسی ندارند** → Phase 1 به‌صورتِ پارامترِ اختیاری (پیش‌فرض ۰). Phase 2 آپشنِ per-ماه می‌سازیم.
- **باکت‌ها = گروهِ دسته‌محصول**؛ فقط index 0 («جواهرتایم») هست. `bucket=0` ثابت بگذار.

## 1) Auth + محل
- Route: `GET /a2crm/v1/tg/finance` زیرِ همان خانوادهٔ `tg/*` در `telegram-api.php`.
- Auth: **`a2_tg_auth`** (هدرِ `x-a2-token` علیه آپشنِ `a2_telegram_token` + allowlist/ratelimit موجود). دقیقاً مثلِ بقیهٔ `tg/*`.
- خطا: `{"ok":false,"msg":"..."}`، موفق: `{"ok":true, ...}`.

## 2) پارامترها
- `month` = ماهِ جلالی `YYYY-MM` (مثل `1405-05`). با هلپرهای موجود (`a2_jalali_to_gregorian`) به بازهٔ میلادیِ اول‌تا‌آخرِ ماه (به وقتِ `Asia/Tehran`) تبدیل کن و همان `from/to`ی صفحه را بساز. نبودِ `month` = ماهِ جاریِ جلالی.
- `fixed_salary` (اختیاری، پیش‌فرض ۰) — ریال.
- `carry` (اختیاری، پیش‌فرض ۰) — «مانده از قبل»، ریال.
- `deposit` (اختیاری) — «واریزشده»؛ اگر ندادند = جمعِ دریافتی‌های بازه (همان پیش‌فرضِ صفحه).
- `bucket` (اختیاری، پیش‌فرض ۰).

## 3) پاسخ
```json
{
  "ok": true,
  "month": "1405-05",
  "month_label": "مرداد ۱۴۰۵",
  "range": { "from": "2026-07-23", "to": "2026-08-22" },   // بازهٔ میلادیِ استفاده‌شده
  "currency": "rial",

  "totals": {
    "commission":           0,   // جمعِ پورسانت (همان محاسبهٔ per-order صفحه)
    "commission_jewel":     0,   // تفکیکِ اختیاری (۴٪ جواهرتایم)
    "commission_non":       0,   // غیرجواهرتایم (۲٪ اسنپ / ۴٪ بقیه)
    "commission_remaining": 0,   // الباقی‌ها (۴٪)
    "receipts":             0,   // جمعِ دریافتی‌ها (دستی + خودکار)
    "expenses":             0,   // جمعِ مخارج (دستی + خودکارِ عودت)
    "deposit":              0,   // واریزشده (پیش‌فرض = receipts)
    "fixed_salary":         0,   // از پارامتر (ذخیره‌نشده)
    "carry":                0,   // مانده از قبل، از پارامتر
    "final_pay":            0    // = fixed_salary + commission − deposit + expenses + carry  (فرمولِ خطِ ۸۰۴–۸۰۷)
  },

  // ریزِ سفارش‌های سهیم در پورسانت (برای شفافیت + تطبیق با صفحه)
  "orders": [
    { "order_id":0, "date":"1405-05-03", "status":"deliver", "total":0, "gateway":"",
      "jewel":0, "non":0, "remaining":0, "commission":0 }
  ],
  // ریزِ دریافتی/مخارج با منبع (manual یا auto)
  "receipts_rows": [ { "id":"", "date":"1405-05-01", "amount":0, "desc":"", "source":"manual|auto" } ],
  "expenses_rows": [ { "id":"", "date":"1405-05-02", "amount":0, "desc":"", "source":"manual|auto_refund" } ],

  "bucket": { "index":0, "title":"جواهرتایم", "cats":[ {"id":25197,"name":"..."} ] },
  "available_months": ["1405-05","1405-04","1405-03"]
}
```

## 4) قواعد
- **دوباره‌استفاده از محاسبهٔ صفحه** (نه بازنویسیِ نرخ‌ها). همان استاتوس‌ها (`processing/completed/delivered/deliver`)، همان proration و منطقِ fix-box، همان دریافتی/مخارجِ خودکار.
- تاریخ‌ها در پاسخ **جلالی** رشته‌ای (با `a2_jalali_format`). مبالغ **ریال، عددِ صحیح**.
- نرمال‌سازیِ تاریخِ ردیف‌های دستی با همان `$a2_comm_date_key` (تا ردیفِ با تاریخِ جلالیِ خام از فیلترِ بازه جا نماند — باگِ شناخته‌شده خطِ ۷۷۴–۷۹۴).
- `available_months`: فهرستِ ماه‌هایی که سفارش/دریافتی/مخارج دارند (برای ناوبریِ ربات).
- کشِ کوتاه‌مدت (چند دقیقه) عاقلانه است چون کوئری `limit:-1` + `wc_get_product` per item است.

## 5) بعد از ساخت
از همان `CRM_TG_URL`/`CRM_TG_TOKEN`ی که الان کار می‌کند استفاده می‌کنم (توکنِ جدا لازم نیست). به‌محضِ زنده‌شدنِ
این route، نمای «حساب مالی» با اعدادِ واقعی کار می‌کند. **Phase 2** بعداً: (الف) آپشنِ per-ماه برای `fixed_salary` و
`carry`؛ (ب) افزودنِ ردیفِ دریافتی/مخارج از داخلِ ربات (POST به `a2_crm_commission_receipts/expenses`).
